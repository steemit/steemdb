# Test Tools

Unified CLI tool for testing and validating steemdb-sync components.

## Installation

Build the tool:

```bash
go build -o bin/test_tools ./cmd/test_tools
```

## Commands

### `jsonl_replay`

Replay operations from a JSONL file (generated by steemd ingest plugin in dry-run mode) to the `cold_ingest` service via HTTP POST.

#### Usage

```bash
./bin/test_tools jsonl_replay -file /path/to/ingest_20260111_081033_778.jsonl
```

#### Options

- `-file`: Path to JSONL file (required)
- `-endpoint`: Ingest endpoint URL (default: `http://localhost:8080/ingest/applied_ops`)
- `-batch-size`: Number of operations per batch (0 = use single endpoint, default: 100)
- `-rate`: Operations per second (0 = no limit, default: 0)
- `-start-block`: Start from block number (0 = from beginning, default: 0)
- `-end-block`: End at block number (0 = to end, default: 0)
- `-verbose`: Verbose output (default: false)
- `-show-errors`: Show HTTP errors (default: true)

#### Examples

```bash
# Send all operations from jsonl file to cold_ingest
./bin/test_tools jsonl_replay -file /path/to/ingest.jsonl

# Send at 1000 operations per second
./bin/test_tools jsonl_replay -file /path/to/ingest.jsonl -rate 1000

# Send only blocks 1000-2000
./bin/test_tools jsonl_replay -file /path/to/ingest.jsonl -start-block 1000 -end-block 2000

# Custom endpoint
./bin/test_tools jsonl_replay -file /path/to/ingest.jsonl -endpoint http://localhost:9090/ingest/applied_ops
```

### `check_data`

Validate MongoDB data integrity for blocks and operations. Checks for missing blocks and orphan operations.

#### Usage

```bash
./bin/test_tools check_data
```

#### Options

- `-env`: Path to .env file (default: look for .env in current directory)
- `-api`: Steem RPC API endpoint for validation (default: `https://api.steemit.com`)
- `-validate-rpc`: Enable RPC API validation (slower but more thorough)
- `-sample-rate`: Sample rate for RPC validation (1 = check all blocks, 100 = check 1% of blocks, default: 100)
- `-work-dir`: Working directory (default: current directory)

**Note**: All MongoDB connection settings (MONGO_USERNAME, MONGO_PASSWORD, MONGO_DATABASE, MONGO_PORT, MONGO_HOST) are read from the `.env` file.

#### Expected Block Range

The tool determines the expected maximum block number using the following priority:

1. `STOP_REPLAY_AT_BLOCK` from `.env` file (if > 0)
2. `meta.sync_state.max_block` from MongoDB

#### Checks Performed

- **Missing blocks**: Detects gaps in block sequence within `[1..expected_max_block]`
- **Orphan operations**: Sample-based check (random sample of operations; verifies each referenced `block_num` exists in `blocks`). Avoids full-collection aggregation timeouts on large datasets. Sampling uses MongoDB `$sample` (pseudo-random over storage order, not strictly uniform). **Running `check_data` multiple times increases coverage**—each run samples a different subset, so several passes give higher confidence.
- **Block coverage**: Reports blocks with zero operations (allowed, but blocks must exist)
- **RPC validation** (optional, with `-validate-rpc`):
  - Validates block IDs match RPC API (failure → exit 1)
  - Validates timestamps match RPC API (failure → exit 1)
  - Compares operations count with RPC API (**warning only**; mismatches are printed but do not cause exit 1, since RPC may differ from local ingest)
  - Shows real-time progress during validation

#### Exit Codes

- `0`: All checks passed (including when only RPC ops_count mismatches exist)
- `1`: Missing blocks, orphan operations, or RPC block_id/timestamp errors

#### Examples

```bash
# Check data using .env file in current directory
./bin/test_tools check_data

# Check data with RPC API validation (validates block IDs, timestamps, and operation counts)
./bin/test_tools check_data -validate-rpc

# Check data with RPC validation and custom API endpoint
./bin/test_tools check_data -validate-rpc -api https://api.steemit.com

# Check data with RPC validation, checking 10% of blocks (sample-rate=10)
./bin/test_tools check_data -validate-rpc -sample-rate 10

# Check data from docker-compose directory
cd test/docker-compose
../../bin/test_tools check_data

# Check data with RPC validation from docker-compose directory
cd test/docker-compose
../../bin/test_tools check_data -validate-rpc
```

#### Output

The tool provides:

- Summary statistics (blocks count, operations count, missing blocks, orphan operations)
- Missing block ranges (concise format: `1-5,10,15-20`)
- Sample orphan operations
- Tail histogram (last 20 blocks with operation counts)
- **Real-time progress** during RPC validation (if enabled)
- RPC validation results (blocks checked, errors by type)
- Colored output for easy reading (green = OK, red = issues)

## Use Cases

1. **Testing cold_ingest**: Use `jsonl_replay` to verify service processes operations correctly
2. **Data validation**: Use `check_data` to ensure data integrity after replay
3. **Debugging**: Identify issues with specific block ranges
4. **Performance testing**: Test with different rates using `jsonl_replay`

## Notes

- `jsonl_replay` reads JSONL files line by line, handling very large files efficiently
- `check_data` requires direct MongoDB connection (not via docker-compose exec)
- Both tools support colored terminal output for better readability
